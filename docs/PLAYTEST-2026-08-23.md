# Playtest review — 2026-08-23 phone capture

A design read of one recorded session, not a spec. Like
[`PLAYTEST-2026-08-22.md`](PLAYTEST-2026-08-22.md) this file is **history**: it
records what an 87-second capture showed on 2026-08-23 and what was concluded
from it. It describes no intended behaviour, so it cannot drift out of sync with
the code. When one of the calls below is made, the rationale goes next to the
code that implements it, and this file stays as the observation that prompted it.

Read alongside the 08-22 review, which this one grades against.

## The artifact

`demo-2.mp4` — 87.9s, 1180×2556 portrait, 60fps HEVC, Safari on iOS against a
LAN dev server (`192.168.0.37`), not the Pages build. Single unbroken run:
0 → **119,225**, chain pinned at ×5.00 from 22s, ending `LOST — OFF COURSE` at
~85.5s having reached **P60 — the last body in the field**.

1.8× the 08-22 session's score (66,326) in the same wall-clock time.

## Method

Everything below is measured off the capture, not impressions.

- Frames pulled at 1fps and read as labelled 8-wide contact sheets; the death
  re-pulled at 4fps.
- Score read visually at 1Hz across all 86 playable seconds. An OCR pass
  (`crop=560:70:320:388`, greyscale, contrast 2.0, negate, 4× lanczos,
  `tesseract --psm 7` with a digit whitelist) was attempted and **abandoned**:
  47 clean readings out of 344. That failure is itself the evidence in §3 — the
  score sits under three other text layers and a planet body.
- Chain multiplier read visually at 1fps.
- Audio checked with `astats` and `showspectrumpic`.
- Claims about mechanism cross-checked against `src/sim/` and `src/score/`
  rather than inferred from the pixels.

Reproduce with the commands in the sections below; the raw frames were scratch
and were not kept.

## What works

**The cadence problem is largely solved.** This was the 08-22 review's §4.

| | 2026-08-22 | 2026-08-23 |
|---|---|---|
| droughts ≥3s | 8 | **0** |
| droughts ≥2s | — | 3 |
| seconds with zero gain | 38% | **25%** |

**The anomaly flipped from the worst-paying stretch to the best.** The 08-22
review's sharpest finding was that spectacle and reward pointed in opposite
directions — the anomaly was the run's longest drought. Scoring rate by phase on
this capture:

| phase | window | pts/s |
|---|---|---|
| opening | 0–22s | 921 |
| mid | 22–49s | 1,219 |
| anomaly 1 | 49–55s | 934 |
| **post-anomaly** | **55–64s** | **3,457** |
| anomaly 2 + top | 64–79s | 1,900 |
| endgame | 79–85s | 139 |

The set piece is now the payoff spike — 3.8× the opening rate. Whatever the
spend-it-later reward and the zip-carry work did, it landed.

**The scar / point-of-no-return marker is the best new UI in the game.** At
40.3s: the dotted projected path, an orange leader from P30 to a gold
ship-marker, and a red ✕ at the last press that still turns you away from the
wall. It answers "am I already dead?" — a question the player previously could
not ask — and it answers it diegetically, on the path, the way the arc gauge
does. Same design DNA as the thing that already worked.

**It looks like a game now.** The 58s frame — purple curtains, ribbon banding,
planets reading through the tint — is finished-product quality, and it is
sustained for ~25 of the 85 seconds rather than the 11 it was on 08-22.

## What doesn't

### 1 — The player finished the game and it was scored as a failure

Highest damage. New, because the run finally got good enough to reach it.

`fieldBounds()` sets `top: highest - 800` (`src/sim/world.ts`) — 800px above the
topmost body. `bodyCount` is 60. The player cleared P60 at ~80s, coasted past
that line, and `stepSim` ended the run `out-of-bounds`.

Frame by frame at 4fps:

```
83.5 – 86.2s   empty black. P60 recedes downward. no planets,
               no edge markers, no red gradient, no scar. 2.7s.
86.5s          score 119,225 -> 0.  ⚠ LOST — OFF COURSE appears.
87.2s          respawned at P1 on a fresh map. BEST 119,225
               in the same tiny grey as the debug readout.
```

Total ceremony: **0.7 seconds** — shorter than the 08-22 session's ~1s, which
that review already called the worst moment in the game.

Three failures are stacked here, and they are separable:

- **The ceiling has no warning treatment at all.** The side walls get a red
  gradient *and* the scar ✕. The trailing floor gets the burn. The ceiling gets
  nothing — no gradient, no marker, no countdown. At 84s the HUD read
  `+500 x5.00 · PEAK 0 · AIM 0` over an empty starfield.
- **60 bodies is ~85 seconds of competent play.** The generator is finite and
  this run outran it. The 08-22 session died at P21 and never saw the edge.
- **Clearing the field is presented as the same event as flying into a wall** —
  same red, same word, same zeroed score.

The game is named for the farthest point of an orbit. Reaching the top of the
field should be the one thing it celebrates.

### 2 — The chain is frozen for 74% of the run

| t | chain |
|---|---|
| 2s | ×1.60 |
| 6s | ×1.80 |
| 9s | ×2.20 |
| 10s | ×2.60 |
| 12s | ×3.00 |
| 15s | ×3.40 |
| 16s | ×3.80 |
| 18s | ×4.20 |
| 20s | ×4.60 |
| **22s** | **×5.00** |
| 22–85s | **×5.00, unchanged for 63 seconds** |

`streakMax: 5` at `streakStep: 0.4` binds on the 11th scoring event. The comment
at `streakMax` argues for "a top a great run touches and an ordinary one does
not"; this capture is the counter-evidence — it is touched at 22s and then the
most prominent progression number on screen says nothing for the remaining 74%
of the session.

Worth stating plainly, because it is the uncomfortable part: the 08-22 review
raised the same complaint at 27 frozen seconds, and the fix that followed —
`streakStep` 0.25 → 0.4 — made it strictly worse by reaching the cap sooner.
That change was measured and correct on its own terms (marginal reward per link,
short lives never reaching the ladder's top); it just optimised the climb while
the plateau was the actual defect.

### 3 — The HUD collision is unfixed, and denser

The 08-22 review's §1 and its first "unambiguous, no design call needed"
recommendation. Full-res crop at 30.0s, untouched:

```
                31,638          <- score, drawn over the body of P21
                  x5.00         <- the chain (orange)
     P23 737 P25 1.2k P22 456   <- planet distance labels, straight through it
          +1,899   x5.00        <- the award's bonus. identical glyph, one line down
     P20 FLYBY · CLOSE 100 · TURN 68°
```

Four text layers plus a rendered planet body in one ~200px band.

The OCR pass is unintentional evidence again, and worse than last time: 47 clean
readings out of 344 attempts, against 132/164 on 08-22. If a program cannot
segment it, a thumb-height glance cannot either.

Both of the 08-22 "no design call needed" items are unshipped:

- no occlusion band — world labels still draw into the HUD strip;
- the persistent chain and the award's bonus are still both rendered `x5.00`, in
  the same face, one line apart.

Under the anomaly tint it is worse: at 58s the grey labels sit on bright purple.

### 4 — The praise vocabulary grew instead of shrinking

The 08-22 review counted 31 unique words and recommended cutting to roughly 1–2
per tier. `praise.ts` now holds **37**, plus 8 in `reckless.ts` — 45 total.

This capture showed **14 distinct words in 85 seconds**: CATAPULT, BRINK, LINED,
TRUE, TRACKING, IMMACULATE, TIMED, SIGHTED, MASTERFUL, STEEL, FLAWLESS, REDLINE,
SLINGSHOT, RECKLESS! — nearly all once each. Identical failure mode: colour does
all the signalling, and no word recurs often enough to become learnable.

### 5 — The game is still silent

`astats` over the full track: `Peak level: -inf`, `RMS level: -inf`,
`Zero crossings: 0`. Not room tone this time — **digital zero**, the capture
having been taken with the ringer muted.

Unchanged from 08-22 as the largest missing feature. For a game whose entire
skill expression is timing a release, there is nothing to time against but the
gauge.

### 6 — Award popups pile up

58s has three on screen simultaneously in three different treatments:

- `SLINGSHOT +2,875` beside the ship, green
- `SLINGSHOT +2,385` fading, grey, lower
- `+842` bare, purple, no word

The same word twice, and a third number with no word at all.

### 7 — There is no difficulty curve

The generator is stationary. `R = 34 + rnd() * 22` at every height, constant
`bodySpacing`, constant `bodyWeave` (`src/sim/world.ts`). P1 and P59 are
statistically identical draws.

So across an 85-second run the only escalation is the player's own accumulated
speed — emergent, not authored — and the multiplier, which stops at 22s. After
the first 25 seconds nothing gets harder or more interesting except the
anomalies, which are placed on an even spread and are therefore also not a ramp.

## Recommendations

### The one unambiguous fix

1. **Give the ceiling the warning treatment the walls already have.** This is an
   inconsistency, not a design call: `fb.left`/`fb.right` get a red gradient and
   a scar ✕, `fb.top` gets nothing, and the machinery needs no special case for
   direction — `src/sim/rescue.ts` answers "can a press still save me" by
   simulating, and does not care which boundary the projection ends at.

### Design calls — measure and confirm before building

2. **Decide what the top of the field is.** The game is currently the worst of
   both shapes: finite content with endless framing, separated by an unmarked
   instant-death line. Two coherent answers —

   - *Endless.* Generate rows lazily as `highWaterY` climbs; delete the ceiling.
     Keeps the current framing honest, costs the game an ending.
   - *A summit.* Keep the 60 bodies and make crossing the top a **win**: freeze,
     pull the camera back over the run's path, name the score, and distinguish it
     from a crash in colour and word.

   Largest quality-per-hour upgrade available, and only the author can make it.

3. **Re-measure the chain ceiling against the run it actually produces.** The
   concrete measurement: rescore the `diagnostics/` corpus and report *what
   fraction of the seconds inside each life sit at `streakMax`*. Note that the
   existing `streakMax` comment already records one mis-tune from too small a
   sample, so this wants the whole corpus, not two sessions. If a good run spends
   most of its life pinned, the ceiling is the wrong *shape* — and then the
   question is not "raise it to 8" but whether the top of the ladder should stop
   being a number that stops moving and become something else.

4. **The HUD band.** Carried unchanged from 08-22, where it was already the
   cheapest real win in the repo. The OCR degradation across the two captures is
   machine-legible proof that it got worse rather than better.

5. **Audio.** Carried unchanged from 08-22. A pitch ramp through the boost arc
   peaking at the release window would teach the core mechanic better than the
   arc gauge does, and would free the player to watch the ship instead of the
   gauge.

6. **Cut `praise.ts` to 1–2 words per tier.** Carried from 08-22, where the pool
   was smaller. A re-measure at coarser granularity, not a re-pick — the
   thresholds are percentiles.

7. **Ramp the generator with height.** Widen `bodySpread`, stretch
   `bodySpacing`, or thin the corridor as `y` climbs, so the back half of the
   field is a different game from the front half.

### Not investigated

- Whether the 50–54s freeze inside the first anomaly is the charge window working
  as designed. It immediately precedes the run's largest payout, so it may be
  correct tension rather than drought — the opposite reading from the 08-22
  anomaly finding, and this capture cannot separate them.
- Whether the endgame collapse to 139 pts/s at 79–85s is purely the field running
  out, or also a scoring artifact of the last bodies being isolated.
- The coast phase still accepts no input. Carried from 08-22 unexamined.
